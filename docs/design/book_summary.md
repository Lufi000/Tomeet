# Tomeet AI 导读设计

状态：产品边界已确认；是否进入正式路线图由 Phase 0 验证结果决定  
适用平台：iOS 17+  
依赖：真实书籍解析、稳定的书籍定位信息，以及服务端内容生成能力

## 0. 定位与边界

Tomeet 的核心仍是高质量 AI 阅读：阅读原文、向书提问、理解概念，并把对话沉淀为个人知识。AI 导读是单本书内的可选能力，帮助用户快速建立全局认识，然后回到原文阅读或继续提问。

本设计不把 Tomeet 改造成以音频消费为主的讲书 App，也不改变现有 Home、Library、Search 根导航。

### 0.1 术语

- **原文朗读**：按照书籍原文顺序进行 TTS。
- **AI 导读**：基于原文重新组织的结构化内容，可同时提供文字稿和音频。
- **引用定位**：导读观点指向其原文依据；EPUB 使用 CFI 或等价定位，PDF 使用页码与文本范围。

### 0.2 用户价值

- 阅读前：用较短时间了解主题、结构与关键问题。
- 阅读中：从导读观点跳回原文，降低理解门槛。
- 阅读后：回顾观点，并围绕原文继续与书对话。

### 0.3 本阶段不做

- 不替换原文阅读器，不弱化翻页、高亮和笔记。
- 不新增 Player 或 Chat 根 Tab。
- 不支持用户上传任意版权书后公开生成或分发导读。
- 不在 iOS 客户端保存模型、TTS 或存储服务密钥。
- 不在供应商验证前固定模型、音色、价格或质量排名。

## 1. 当前工程基线

截至 2026-08-17，工程已经具备：

- SwiftUI `TabView`：Home、Library、Search。
- 每个主页面独立使用 `NavigationStack`。
- SwiftData `Book` 与 `ReadingGoal` 模型及幂等种子数据。
- Home 的 Continue、Previous、Reading Goals。
- Library 的网格/列表、排序菜单和 Collections Sheet。
- 可从 Home、Library 打开的全屏阅读器占位页。
- Swift Testing 模型、种子数据和展示逻辑测试。

尚未具备：

- EPUB/PDF 导入、解析和稳定的原文定位。
- 真实阅读器、播放服务和本地媒体缓存。
- 服务端 API、任务队列、对象存储与 AI 对话。
- 导读产物的数据模型和 UI。

因此 AI 导读不能直接作为当前 Milestone 1 的增量功能，应在真实阅读器能够提供稳定原文定位后接入。

## 2. 产品体验

### 2.1 入口

AI 导读属于一本书，不是独立内容频道。入口按优先级为：

1. 阅读器菜单中的 `AI Guide`。
2. Library 书籍菜单中的 `AI Guide`。
3. Home Continue 卡片的更多菜单。

没有导读的书明确显示 `AI Guide unavailable`，不展示无响应入口。

### 2.2 导读页

导读页使用单独的 SwiftUI 页面，包含：

- 书籍封面、书名和作者。
- 导读标题、预计收听时间和生成版本。
- 播放/暂停、前后跳转、倍速和进度。
- 按主题组织的章节列表。
- 当前章节对应的文字稿。
- `Read in Book`：跳转到当前观点的原文依据。
- 后续 AI 对话上线后的 `Ask about this`。

iPhone 使用单列布局。音频控制保持在导读页内，不改变根导航。关闭导读后回到原书上下文。

### 2.3 核心闭环

```text
选择一本书
  → 打开 AI 导读
  → 收听或阅读某个观点
  → 查看原文依据
  → 回到原文阅读
  → 针对该观点继续提问
```

### 2.4 状态

页面必须显式覆盖：

- `unavailable`：该书没有导读。
- `preparing`：服务端正在生成。
- `ready`：文字稿可用，音频可播放或下载。
- `downloading`：显示可取消的确定进度。
- `failed`：显示可追踪错误和重试入口。
- `outdated`：书籍源文件变化，旧导读不可继续关联原文。

## 3. 内容结构与质量要求

AI 导读不是压缩原文，也不能代替原书。每份导读由 3–7 个主题章节组成，每个章节包含：

- 用户能理解的问题或主题。
- 作者的核心观点。
- 支撑观点的案例、论证或情节。
- 对适用边界的说明。
- 一段导读叙述。
- 至少一个可验证的原文引用定位。

不强制固定字数。目标时长由书籍类型和信息密度决定，首轮实验建议控制在 15–30 分钟。

### 3.1 生成流程

服务端采用可审计的多阶段流程：

1. **解析**：按章节提取文本与稳定定位，计算源文件指纹。
2. **理解**：逐章提取人物、论点、证据和章节关系。
3. **规划**：生成全书导读提纲，并为每个观点绑定原文依据。
4. **写作**：按照提纲生成口语化叙述，不模仿特定个人或品牌风格。
5. **校验**：检查观点是否有依据、引用是否存在、专有名词是否一致。
6. **合成**：按章节生成音频并记录时间轴。
7. **发布**：生成带版本和校验值的导读清单。

任何没有原文依据的事实性内容都不得进入最终产物。校验失败时应停止发布，而不是静默降级。

### 3.2 结构化产物

导读清单至少包含：

- `schemaVersion`
- `bookID`
- `sourceFingerprint`
- `locale`
- `generatedAt`
- `duration`
- `spoilerLevel`
- `audioChecksum`
- `sections`

每个 section 至少包含 `id`、`title`、`transcript`、`audioStart`、`audioEnd` 和 `citations`。供应商原始响应不作为客户端协议，避免客户端绑定具体模型。

## 4. 应用架构

遵循现有 SwiftUI + 简单 MVVM，不引入 Repository、UseCase、全局 Store 或第三方架构。

- `BookSummaryView`：只负责展示与用户操作。
- `BookSummaryViewModel`：维护页面状态、播放意图和错误提示。
- `BookSummaryService`：获取并验证导读清单。
- `AudioPlaybackService`：封装 `AVPlayer` 播放和时间观察。
- `BookSummaryDownloadService`：负责下载、校验、取消和删除缓存。
- 阅读器定位接口：接收 citation，并导航到 EPUB CFI 或 PDF 页码。

服务通过初始化参数显式注入 ViewModel。网络请求、文件读写和音频实现细节不能进入 View 或 ViewModel。

### 4.1 数据流

```text
预处理服务 → 结构化导读 + 分段音频 → 受控存储
       ↓
BookSummaryService → ViewModel → BookSummaryView
       ↓                 ↓
原文定位接口       AudioPlaybackService
```

生成使用的模型与 TTS 可通过服务端配置替换。客户端只依赖稳定协议。

### 4.2 本地数据

在体验验证前不修改现有 `Book` 模型。原型使用随 App 提供的 1 本公版书导读 fixture。

进入联网阶段后，再为导读状态、版本、下载位置和播放进度建立独立 SwiftData 模型；大段文字与音频存放在文件系统，不写入 SwiftData。源文件指纹变化时必须使关联导读失效。

## 5. 安全、版权与隐私

- 客户端只访问 Tomeet 服务端，不直接携带第三方密钥。
- 服务端对下载地址设置访问控制和有效期。
- 首轮只使用已核实权利状态的公版书或已获授权内容。
- 用户私有书籍不得进入公共导读库，也不得用于其他用户的生成结果。
- 原文片段只保留完成定位和校验所需的最小范围。
- 每份导读记录来源版本、生成版本和发布时间，支持下架与失效。

公版状态必须按作者、译者、版本和目标发行地区分别核实，不能仅依据书名判断。

## 6. 失败处理

- 清单请求失败：保留当前页面，显示重试，不伪装为空内容。
- 音频下载中断：有有效恢复数据时续传，否则从头重试；两种情况都保留明确进度。
- 校验值不匹配：删除损坏文件并报告错误。
- 音频不可用但文字稿完整：明确提示后允许只读文字稿。
- 引用定位失效：禁用 `Read in Book`，记录错误，不跳转到近似位置。
- App 进入后台或音频被系统中断：遵循 `AVAudioSession` 系统行为并保存进度。

## 7. 分阶段路线

### Phase 0：离线体验验证

- 选择 1 本权利状态明确的公版书。
- 人工审核一份结构化导读和音频 fixture。
- 实现导读页、播放、章节切换和占位原文跳转。
- 不接模型、不接云端 TTS、不修改 SwiftData。

验收：用户可从一本书进入导读，完成播放与章节切换，并返回原书上下文。

### Phase 1：预生成内容接入

- 服务端预生成少量公版书导读。
- App 获取清单、下载音频、校验并缓存。
- 建立独立的导读本地状态模型。
- 真实阅读器完成引用跳转。

验收：断网可播放已下载内容；损坏缓存可恢复；每个观点可跳到正确原文。

### Phase 2：与 AI 对话连接

- 从导读章节发起上下文明确的问题。
- 回答同时检索导读与原文，但以原文为最终依据。
- 对话记录可沉淀为笔记和个人知识。

验收：回答能区分导读解释与原文事实，并提供可访问的原文依据。

### Phase 3：按需生成

- 用户为有权处理的私有书籍发起异步生成。
- 提供排队、进度、失败重试、取消和删除。
- 基于真实数据评估成本、时延和供应商。

此阶段必须在版权、隐私、配额和内容删除机制确认后启动。

## 8. 质量与测试

- 单元测试：清单解码、版本兼容、状态转换、校验失败和源文件失效。
- Service 测试：成功、空响应、超时、取消、损坏文件和重复下载。
- ViewModel 测试：播放意图、章节切换、错误展示和恢复。
- 集成测试：导读章节到 EPUB/PDF 原文定位。
- 人工评审：事实准确、引用有效、叙述自然、没有未标记剧透或过度简化。
- 真机验证：后台播放、耳机控制、系统音频中断、锁屏恢复和离线播放。

供应商选择以同一组书籍样本盲测，至少比较准确性、引用可靠性、中文自然度、首包延迟、生成时长和单位成本。评测结果单独记录，不把易过期的价格与模型参数硬编码在本设计中。

## 9. 对现有工程的影响

当前设计文档不要求立即修改代码。后续实现应保持局部增量：

- 保留 `RootView` 的三个系统 Tab。
- 保留现有 `Book` 与 `ReadingGoal` 数据模型。
- 在真实阅读器稳定后新增独立 `BookSummary` feature。
- 不影响没有 AI 导读的书籍阅读流程。

该能力是否进入正式路线图，以 Phase 0 的用户体验验证结果为准。
